# CJ-0005 — Written on the Wall II, Conjecture 199

*Compiled 2026-11-26 from the record of a literature-scout subagent (Claude, model `claude-fable-5-2`), lightly reformatted. It is a preliminary dossier: it has not been independently audited, and every item under “Unverified items” must be checked before it is relied upon.*

## Statement

Verbatim from the WOWII list: "If G is a simple connected graph with n > 1 such that tree(G) - 2 ≤ κ(G), then G has a Hamiltonian path." Definitions, verbatim from the list's definitions script (wowIIdefs.js): tree(G) = "The number of vertices of a largest induced tree of the graph."; κ(G) (connectivity number) = "is the fewest number of vertices whose removal disconnects the graph."; Hamiltonian path = "A graph is said to have a Hamiltonian path if there exist two vertices with a path between them which visits each vertex of the graph exactly once." n is the number of vertices.

**Source.** E. DeLaViña, Written on the Wall II (Conjectures of Graffiti.pc), entry 199, dated 12 January 2006; read from the Internet Archive snapshot of 2026-07-23. <https://web.archive.org/web/20260723161800id_/http://cms.uhd.edu/faculty/delavinae/research/wowII/all.html>

**Statement checked against:** primary-source. Read from an archived copy because the live host timed out.

## Definitions and hypotheses

G finite, simple, connected, n > 1. 'Induced tree' means an induced subgraph that is a tree (connected and acyclic); it need not be spanning. The WOWII definition of κ is undefined for complete graphs; the usual convention κ(K_n) = n-1 must be fixed explicitly (the Lean statement in google-deepmind/formal-conjectures uses its own `vertexConnectivity`, with an explicit clause for removing n-1 vertices). For connected G with n > 1 one has tree(G) ≥ 2, so the subtraction is harmless, but in Lean it is natural-number (truncated) subtraction. Conclusion is a Hamiltonian PATH, not a cycle.

## Computational approaches

Exhaustive check over all connected graphs with nauty/geng: tree(G) by bitmask enumeration of vertex subsets, κ(G) by max-flow or brute force, Hamiltonian path by Held-Karp DP; n ≤ 10 is routine in C or compiled Python, n = 11 is feasible on a desktop with compiled code. Targeted search is better than brute force: a counterexample must be non-traceable with κ ≥ tree - 2, so stratify by κ = k and search graphs with no induced tree on k+3 vertices (for k = 1: no induced P4 and no induced claw). SAT/SMS (SAT Modulo Symmetries) encoding 'no induced tree on k+3 vertices, k-connected, no Hamiltonian path' is plausible for n up to about 14-16. No verified range is stated in any source fetched.

## Mathematical approaches

Contrapositive: every connected non-traceable graph contains an induced tree on at least κ(G)+3 vertices. Natural route: adapt the Chvátal–Erdős longest-path argument (which produces an independent set of size κ+2 in a non-traceable graph) to produce an induced tree; handle κ = 1 first (connected graphs with no induced tree on 4 vertices, i.e. {P4, claw}-free), then κ = 2, then restricted classes (bipartite, claw-free, chordal, cographs). Characterising equality cases (complete bipartite K_{a,a+1}) is a possible by-product.

Scout's tractability assessment: Good newcomer target. Realistic partial progress: exhaustive verification to n = 10 or 11; a proof for κ = 1 and perhaps κ = 2; a proof for one or two hereditary classes; or a counterexample found by structured search (conjecture 200 fell to a pendant-vertex construction). Sibling open entries in the same repository are equally approachable: 40 (separate record), 61 (f(G) ≥ res(G) + CEIL[diam(G)/3]), 84 (tree(G) ≥ 2rad(G)/δ(G)), 72, 96, 133, 189. Entry 372 looks nearly closed: the WOWII page itself reduces it to path-cover number 2 and the Lean file cites a Gebendorfer manuscript on exactly that case. Main risk is being scooped, not difficulty.

Basic graph theory (connectivity, Menger, induced subgraphs), Dirac / Ore / Chvátal–Erdős style Hamiltonicity arguments, use of nauty (geng) and a SAT solver, elementary Lean 4 with Mathlib's SimpleGraph API.
